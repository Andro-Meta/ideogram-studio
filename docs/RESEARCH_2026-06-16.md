# Ideogram 4 Ecosystem Research — What to Port Into the Studio

**Date:** 2026-06-16
**Scope:** Survey the public Ideogram 4 ecosystem (GitHub `ideogram-4` topic + Hugging Face), compare it to what our studio already does, and identify unique/exciting features worth porting — with the gaps, conflicts, and a build order.
**Method:** Reviewed all 4 repos under https://github.com/topics/ideogram-4, the ComfyUI custom nodes they ship, and the Hugging Face model/space ecosystem. Cross-checked every idea against our current backend/frontend.

---

## TL;DR — the shortlist

Most of the community's "tooling" is **thin wrappers around Ideogram's hosted Magic Prompt API** — and we already do more than they do, locally. The genuinely portable, exciting ideas are smaller and sharper:

1. **Artifact-suppression / pseudo–negative-prompt** (from `hardhant`) — the *correct* way to give users a "negative prompt" on a model that has none. **Highest-value, lowest-effort. Build it.**
2. **Megapixel-driven resolution selector + the full 18 native aspect ratios** (from `Saganaki22`) — we're missing 8 of Ideogram's native ratios (the panoramic/strip extremes) and the "pick ratio, dial MP" UX.
3. **Built-in prompt/template library** (from `EvoLinkAI/awesome-ideogram-4.0-prompts`) — bundle curated structured-caption starters for onboarding and inspiration.
4. **Scene preset save/load + a headless CLI** (from `jonasnordlund/intuition`) — export/import the whole caption+layout as a reusable file; script Generate/Remix/Describe.
5. **GGUF + INT8/SDNQ quant paths** (from the HF quant ecosystem) — let sub-24 GB GPUs run the model. Bigger lift, broad reach.
6. **Local image captioner backend (JoyCaption / CLIP-Interrogator)** for Image→Prompt — a privacy-preserving alternative to the OpenRouter vision call.
7. **Community LoRAs + an Inpaint LoRA** (HF) — curate a one-click LoRA gallery; evaluate `BitPoet/Ideogram4-Inpaint-LoRA` against our RePaint inpaint.

Everything else they've built, we already have (Magic Prompt, bbox editor, Describe, Remix, palettes, gallery).

## 1. What's actually out there

| Repo | Stars | What it is | Portable idea |
|---|---|---|---|
| [`EvoLinkAI/awesome-ideogram-4.0-prompts`](https://github.com/EvoLinkAI/awesome-ideogram-4.0-prompts) | 29 | Curated prompt + example library (typography, photoreal portraits, product/UI mockups, model comparisons) | A **built-in prompt/template gallery** |
| [`Saganaki22/ideogram4_prompter-ComfyUI`](https://github.com/Saganaki22/ideogram4_prompter-ComfyUI) | 7 | ComfyUI nodes: Magic Prompt + **Resolution Selector** (aspect → megapixel → W/H, ×8) with the **full 18 native ratios** + `AUTO` | **MP-driven resolution control**; complete native ratio list |
| [`hardhant/ComfyUI-AliAn-Ideogram-Magic-Prompt`](https://github.com/hardhant/ComfyUI-AliAn-Ideogram-Magic-Prompt) | 2 | Magic Prompt node + **"Suppress Artifacts" node** (positive-constraint snippet as a stand-in for negative prompts); strips `bbox`/`aspect_ratio` echoes | **Artifact-suppression / pseudo-negative-prompt** |
| [`jonasnordlund/intuition`](https://github.com/jonasnordlund/intuition) | 0 | Web bbox/JSON editor with **save/load of settings** + a **CLI** (`ideogram.py`: Generate / Remix / Magic Prompt / Describe) | **Scene presets**; **headless CLI** |

**Reality check:** all three code repos are **API-only** — they call `api.ideogram.ai/.../magic-prompt` and send your prompt + key to Ideogram's cloud. None run weights locally. Our studio's whole premise (local generation, nothing leaves the box) is *ahead* of these; the value is in their UX ideas, not their architecture.

### 1.2 Hugging Face — the real action is models/quants/LoRAs

Ideogram 4's open weights are real and active (released ~May 30, 2026): `ideogram-ai/ideogram-4-fp8` (557 likes), `-nf4`, `-nf4-diffusers`, plus the official [`ideogram-ai/ideogram4` Space](https://hf.co/spaces/ideogram-ai/ideogram4) and [`Comfy-Org/Ideogram-4`](https://hf.co/Comfy-Org/Ideogram-4).

What the community has added that we **don't** consume:

- **Quantizations for smaller GPUs:** a large GGUF family ([`leejet`](https://hf.co/leejet/ideogram-4-GGUF), `stduhpf`, [`transformerlab` q4_k/q8_0](https://hf.co/transformerlab/ideogram-4-gguf-q4_k), `Abiray`, `rectangleworm`, `molbal`), plus **INT8** ([`transformerlab/...-int8-w8a8`](https://hf.co/transformerlab/ideogram-4-int8-w8a8), [`bertbobson/Ideogram-4-INT8-ConvRot`](https://hf.co/bertbobson/Ideogram-4-INT8-ConvRot)) and **SDNQ-FP8** ([`Disty0`](https://hf.co/Disty0/Ideogram-4-SDNQ-FP8)). These target stable-diffusion.cpp / ComfyUI and can run below our 24 GB floor.
- **Style LoRAs:** [`RazzzHF/Realism_Engine_Ideogram_4`](https://hf.co/RazzzHF/Realism_Engine_Ideogram_4) (107 likes), [`DeverStyle/Ideogram-4.0-Loras`](https://hf.co/DeverStyle/Ideogram-4.0-Loras), [`jmanhype` Ektachrome film LoRA](https://hf.co/jmanhype/Ektachrome-LoRA-v1-Ideogram-v4), [`multimodalart/tarot-ideogram-4`](https://hf.co/multimodalart/tarot-ideogram-4), `tsolful` fantasy-realism refiner.
- **An Inpaint LoRA:** [`BitPoet/Ideogram4-Inpaint-LoRA`](https://hf.co/BitPoet/Ideogram4-Inpaint-LoRA) — a learned inpaint adapter, architecturally different from our training-free RePaint blend.
- **An "unconditional" LoRA:** [`ostris/ideogram_4_unconditional_lora`](https://hf.co/ostris/ideogram_4_unconditional_lora) — relevant to the uncond/CFG-collapse work in the 06-14 audit (running near CFG 1).
- **Local image captioners** (Spaces) usable as a local Image→Prompt backend: [JoyCaption Beta One](https://hf.co/spaces/fancyfeast/joy-caption-beta-one), [CLIP-Interrogator](https://hf.co/spaces/pharmapsychotic/CLIP-Interrogator).

## 2. What we already have (don't rebuild these)

Our studio already covers the community's headline features, usually more completely:

- **Magic Prompt** — 3 backends (Ideogram API / OpenRouter free / local LLM). Supersedes both ComfyUI prompter nodes.
- **Visual bbox + JSON editor** — `BBoxCanvas`, element list, per-element + global hex palettes, Photo/Illustration modes. Supersedes `intuition`'s web editor.
- **Image→Prompt (Describe)** — vision-model reverse-prompting (`magic_prompt_service.describe_image`). Matches `intuition` CLI's Describe.
- **Remix / img2img blend, inpaint, outpaint/extend, split-to-layers, upscale (AuraSR + optional PiD).**
- **CFG curve controls, empty-canvas guard, auto seed-retry on collapse** — already landed per `IMPLEMENTATION_2026-06-14.md`.
- **LoRA loading** (`.safetensors` or HF repo) on NF4·D / BF16. We can *load* LoRAs; we just don't *curate* them.
- **Resolution:** 10 standard + 10 HD aspect presets, custom W/H (256–2048, ×16), auto aspect-match (~1 MP) from an uploaded image.

## 3. Gaps — concrete features to port

Ranked by value ÷ effort.

### P0 — Artifact suppression / pseudo–negative-prompt  *(port from `hardhant`)*
Ideogram 4 has **no negative-prompt field**; users still want one. The community fix is to inject *positive* constraints instead: "sharp focus, no motion blur", "clean signal, no grain", "high fidelity, no compression artifacts", "accurate color, no chromatic aberration".
- **Why it's exciting:** it resolves a real UX gap *and* the 06-14 audit's explicit "don't add a negative box" rule — this is the safe, on-model way to do it.
- **Build:** a toggle + small editable preset list that appends a constraint clause to `style_description`/high-level text at caption-assembly time (`backend/caption.py` / `frontend/src/lib/caption.ts`). Optionally a standalone "apply to existing caption" action like their second node.
- **Effort:** ~half a day. No model changes.

### P0 — Full native aspect-ratio set + megapixel selector  *(port from `Saganaki22`)*
We expose 10 ratios; Ideogram natively accepts **18** (`AUTO`, `1x4, 1x3, 1x2, 9x16, 10x16, 2x3, 3x4, 4x5, 1x1, 5x4, 4x3, 3x2, 16x10, 16x9, 2x1, 3x1, 4x1`). We're missing the panoramic/strip extremes (`1x4/4x1`, `1x3/3x1`, `1x2/2x1`, `10x16/16x10`).
- **Add:** the missing ratios to `ASPECT_RATIO_PRESETS`, plus a **megapixel slider** that computes W/H from the chosen ratio (snap to ×16 for our pipeline; they use ×8). Research (audit T7) says higher res → better skin/detail up to 2048², so a clean MP dial is genuinely useful.
- **Add (optional):** an `AUTO` ratio that takes the aspect ratio the Magic Prompt response resolves to.
- **Effort:** ~half a day, frontend-mostly.

### P1 — Built-in prompt/template library  *(inspired by `EvoLinkAI`)*
Ship a browsable gallery of ready-made **structured captions** (typography, product/UI mockups, portraits, posters) that load straight into the editor. Huge onboarding/inspiration win; nobody else bundles this with a local app.
- **Build:** a JSON pack of curated captions + a "Templates" panel that hydrates `PromptStateModel`. Author our own examples (avoid copying their text wholesale).
- **Effort:** 1–2 days incl. authoring content.

### P1 — Scene preset save/load + headless CLI  *(port from `intuition`)*
- **Presets:** export/import the full caption + bbox layout + palette as a named `.json` you can reuse or share. We persist *generations* in the gallery but have no reusable *recipe* concept.
- **CLI:** a thin `ideogram_cli.py` over existing backend functions for Generate / Remix / Describe / Magic Prompt — enables batch jobs and scripting without the web UI.
- **Effort:** presets ~1 day; CLI ~1–2 days.

### P2 — Quant paths for smaller GPUs (GGUF / INT8 / SDNQ)  *(from HF)*
Our floor is 24 GB. The GGUF (q4_k/q8_0) and INT8/SDNQ builds run lighter. Supporting a GGUF path (via stable-diffusion.cpp or a ComfyUI-style loader) would open the studio to 12–16 GB cards.
- **Effort:** large — a new inference backend + loader + model-variant entries. Stage as its own project; biggest reach.

### P2 — Curated LoRA gallery + Inpaint-LoRA eval  *(from HF)*
We can load LoRAs but don't surface good ones. Add a **one-click LoRA browser** seeded with vetted HF repos (Realism Engine, Ektachrome, tarot, etc.) using our existing apply/weight/remove plumbing. Separately, **benchmark `BitPoet/Ideogram4-Inpaint-LoRA`** against our RePaint inpaint — a learned adapter may give cleaner edits.
- **Effort:** LoRA gallery ~1 day; inpaint-LoRA eval is GPU-gated R&D.

### P3 — Local Image→Prompt backend (JoyCaption / CLIP-Interrogator)  *(from HF Spaces)*
Add a **local** captioner option to Image→Prompt so reverse-prompting works fully offline (no OpenRouter). Fits the privacy-first stance.
- **Effort:** medium — bundle/serve a captioner; new backend branch in `magic_prompt_service`.

## 4. Conflicts to resolve before porting

1. **Local-first vs. hosted API.** Every ComfyUI repo sends your prompt + API key to Ideogram's cloud. Porting their *features* is fine; porting their *dependency* is not. Implement these locally (our Magic Prompt already offers the Ideogram API as one *optional* backend, so we stay consistent). Don't make any new feature require the hosted API.

2. **"Negative prompt" expectations.** The 06-14 audit (T11) correctly forbids a text-negative box — the model uses an uncond *model*, not text. The `hardhant` artifact-suppression approach is the reconciliation: market it as "Quality constraints / artifact suppression," **not** "negative prompt," and keep it positive-phrased.

3. **Resolution alignment (×8 vs ×16).** Their Resolution Selector rounds to ×8; our pipeline requires ×16 (confirmed a hard requirement, not the non-bug ×32 myth from the audit's B4). When we port the MP selector, snap to ×16, not ×8.

4. **Caption schema drift.** Their nodes strip `bbox`/`aspect_ratio` from the caption; ours is **bbox-native** (boxes are the core feature and the anti-collapse mechanism). Don't adopt their bbox-stripping — keep boxes; only mirror their habit of not echoing `aspect_ratio` inside the caption JSON.

5. **Quant backends are a parallel stack.** GGUF/INT8/SDNQ don't drop into our diffusers `Ideogram4Pipeline`; they need their own loader/runtime. Treat as an additive backend behind the model-variant switch, not a refactor of the current path.

---

## 5. Suggested build order

1. **Artifact-suppression toggle + presets** (P0) — fastest visible win; closes a real gap on-model.
2. **Full native ratios + megapixel selector** (P0) — small, high-utility, pairs with the resolution/quality research.
3. **Prompt/template library** (P1) — onboarding and "wow" factor; differentiates us from every API wrapper.
4. **Scene presets + CLI** (P1) — power-user reach and shareability.
5. **LoRA gallery** (P2) + **inpaint-LoRA eval** (GPU) — leverage the growing HF LoRA scene.
6. **GGUF/INT8 quant backend** (P2) — separate track; unlocks smaller GPUs.
7. **Local captioner for Image→Prompt** (P3) — completes the offline story.

Items 1–4 are all CPU-testable and need no model changes; 5–7 are GPU-gated or larger backend work.
