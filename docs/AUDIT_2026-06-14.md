# Ideogram 4.0 Local Studio — System & GUI Audit

**Date:** 2026-06-14
**Scope:** Front-end ↔ back-end wiring, bugs/gaps/conflicts, and a research-driven plan to implement the ComfyUI-community techniques (quality + anti-"safety-collapse") for Ideogram 4.
**Status:** Findings + implementation plan. No code changed yet — awaiting your go-ahead per item.

---

## Executive summary

The system is in much better shape than "half-wired." Every backend endpoint has a frontend caller, every hook is used, and there are **no TODO/FIXME stubs or empty handlers** anywhere in the tree. The real issues are narrower and more interesting:

1. **The generation control surface is locked down.** The underlying diffusers pipeline exposes far more than the UI does — most importantly a **per-step CFG schedule (`guidance_schedule`)**, plus `mu`/`std`. Today the user gets three opaque presets and one boolean (`soft_guidance`). The single highest-leverage change in this whole audit is **exposing CFG + a "CFG-override start %" control**, which is exactly the lever the Banodoco/ComfyUI community uses for both quality *and* avoiding the model's spurious refusals.

2. **The "safety collapse" is a robustness artifact, not a real filter — and it's addressable in-app.** The community consensus (incl. Kijai, the ComfyUI core dev who wrote the integration) is that the gray "blocked" output is the model *collapsing out of distribution* on short / non-JSON / empty-canvas prompts, **not** a server-side filter. You already implement the biggest mitigation (mandatory JSON captions + bounding boxes). The missing pieces are (a) lower/controllable CFG, (b) a **short-prompt / empty-canvas guard**, and (c) **auto seed-retry on a detected collapse** (Kijai: "any fix is about the same as just changing seed").

3. **A handful of genuine bugs**, two of which are user-facing: the **Settings Save button stays disabled when only a toggle changed** (you can't persist moderation / auto-structure / free-models switches on their own), and the **"Generate from image" remix reports seed 0 / 0.0s** and saves files as `ideogram-0.png`.

4. **One state conflict:** the model variant has two sources of truth (client `settingsStore` vs server `settings.model_variant`); the server value is fetched and silently ignored.

This report is ordered by your stated priority: **research features first**, then wiring, then bugs, then a sequenced roadmap.

> **Scope note on "uncensored":** the techniques below are standard diffusion generation controls (CFG value, CFG scheduling, sigma schedule, sampler, prompt structure) that improve output quality and reduce the documented out-of-distribution collapse. I'll implement those as first-class controls. I will not build features whose purpose is generating sexual content involving minors, or tooling aimed at replicating real, identifiable people's likenesses — those stay out regardless of settings. Everything else in the plan is fair game.

## 1.3 Gaps to implement (prioritized)

**P0 — CFG value + CFG-override control (highest leverage).**
Replace the single `soft_guidance` boolean with real controls:
- `cfg` (main guidance, default **3.5**, range ~1–10) — the community's #1 quality fix.
- `cfg_override` (low value for the tail, default ~2.0, range 1–7).
- `cfg_override_start` (fraction 0–1, default **0.7** = override the last 30%).
- Backend builds the `guidance_schedule` list from these (high for first `start×N`, low for the rest), respecting each pipeline's list direction. The plumbing (`guidance_schedule` param) already exists; we're only generating the list from user values instead of from a frozen preset. Keep the three presets as named starting points that pre-fill these fields.
- Feasibility: **trivial-to-moderate.** `Ideogram4Pipeline.__call__` already takes `guidance_schedule: list[float]` of length `num_inference_steps` (`pipeline_ideogram4.py:477`). This is the single change that delivers most of the research's value.

**P0 — Lower default CFG / better preset defaults.**
Today presets bake CFG 7.0→3.0. The community is unanimous that **7 is too high** for photos/realism. Ship the new CFG controls defaulting to ~3.5 with a late drop. (One-line behavior change once P0 controls exist.)

**P1 — Short-prompt / empty-canvas guard (collapse prevention).**
The #1 documented cause of the gray "blocked" output is short prompts / empty canvas, not a filter. Add:
- A token/length check on the assembled caption with an inline warning ("Ideogram collapses on short prompts — add a sentence to the background or a box"). Kijai notes there's a soft minimum nobody has pinned down; the node uses an approximate token count (line 1083).
- An "auto-fill background" affordance: if the canvas has no full-coverage box, offer to add a `[0,0,1000,1000]` background element from the high-level description (the exact "fill the empty space with a background box" trick, lines 763/792). The model treats unboxed regions as "transparent/canvas," which is what triggers the collapse and the fake-alpha artifact (lines 66, 763, 1193).

**P1 — Collapse detection + auto seed-retry.**
The most reliable "fix" in the research is **changing the seed** (T9). Add optional logic: after generation, cheaply detect a collapse (e.g. near-uniform / low-variance gray frame, or the characteristic fake-alpha), and if detected and the seed wasn't user-locked, **auto-retry with a new seed** up to N times. This directly automates what the community does by hand and needs no model changes.

**P2 — Expose steps + mu/std/shift ("advanced" panel).**
Let power users set custom steps and the `mu`/`std`/shift knobs (research: shift 5 + cfg-start 0.4 + simple scheduler fixed splotchy photos, line 1406). Low risk: these are already pipeline params, just frozen in presets.

**P2 — "Fast tail" (cfg→1 on late steps).**
When the override value hits 1.0, the uncond pass can be skipped for ~2× speed on those steps (research lines 845–848). Worth wiring once the CFG-override control exists; verify the diffusers path actually short-circuits at gw=1.0 (ComfyUI needed an explicit fix for this).

**P3 — Custom sigma schedule ("ExtendIntermediateSigmas").**
The diffusers pipeline computes sigmas internally from `mu`/`std` via `_logit_normal_sigmas` and calls `scheduler.set_timesteps(sigmas=...)` (`pipeline_ideogram4.py:614`); `__call__` does **not** accept a custom sigma list. Implementing the "remove the sudden initial-sigma drop" trick means either patching the pipeline to accept `sigmas=` or post-processing the computed schedule. **Recommend deferring / making it experimental:** the research itself is split on whether it helps ("makes outputs bad," and Kijai says it ≈ a seed change). Low ROI vs. P0/P1.

**P3 — Perf: flash-attention path.**
Ideogram's head dim is 256, where FlashAttention gives a real win and SageAttention does nothing (T13). If the local torch build supports FA2, enabling it for the transformer is a measurable speedup (1.15–1.73× on attention). Investigate as an install-time/runtime option; note torch.compile currently degrades quality (line 834) so leave it off.

**Out of scope / not applicable:**
- Negative-prompt textbox — model has no text negative (T11). Don't add.
- nvfp4-uncond / int8 QuantOps loaders — these are ComfyUI-specific quant paths; your stack standardizes on nf4d via diffusers. Note for the future but not a port target.

# Part 2 — Front-end ↔ back-end wiring

**Headline: wiring is largely complete.** Every one of the ~30 backend routes has a caller; every hook is used by a component; the WebSocket generation path is solid. The gaps are small.

### 2.1 Confirmed-good wiring
REST gallery/settings/system/model/magic-prompt/describe/fuse/enhance/loras/upscale/import/edit(inpaint,extend,save,layers)/logs all have matching hooks, and the `/ws/{job_id}` flow (single + batch) is correctly wired with progress callbacks.

### 2.2 Wiring gaps / loose ends

1. **`EditRequest` type is orphaned (vestige of an unbuilt endpoint).** `types/api.ts:176` defines a server-side adjust request (`rotate/flip/brightness/contrast/saturation/sharpness`) that **nothing calls** — there is no `/api/edit` adjust route. The editor instead does all adjustments client-side and only POSTs the flattened PNG to `/api/edit/save`. Also its fields don't match the editor's actual adjustments (`editorTypes.Adjustments` has `hue`/`blur`; `EditRequest` has `sharpness`). **Action:** delete the dead type (or build the endpoint if server-side adjust is wanted — it isn't needed since flatten-and-save works).

2. **Server `settings.model_variant` is fetched but never read.** `GET /api/settings` returns `model_variant`, but the UI drives everything off `settingsStore.modelVariant` (localStorage). The server's persisted default is silently ignored → see Conflict #1 below.

3. **`EditResponse.width/height` returned but never consumed** by any of the five edit hooks. Harmless dead fields; either use them (e.g. to update canvas size after extend) or drop them from the type.

4. **`/api/edit/inpaint` & `/api/edit/extend` bypass two systems the WS path has:** they ignore `soft_guidance` (always use the frozen preset schedule, `inference.py:583`) and **skip Hive moderation** entirely. If moderation is meant to be a hard gate, edits are a hole; if `soft_guidance`/CFG control is meant to be global, edits don't honor it. **Action:** thread the (new) CFG controls through the edit pipeline too, and decide moderation policy for edits.

5. **`MagicPromptService.rebuild()` is dead code** (`magic_prompt_service.py:200`) — never called; settings updates reconstruct the whole service instead. Remove or wire.

# Part 3 — Bugs, gaps & conflicts

### 3.1 User-facing bugs

**B1 — Settings Save disabled on toggle-only changes (real bug).**
`pages/Settings.tsx` Save button `disabled` check only considers the three key fields + `mpBackend`. But `handleSave` also sends `openrouter_free_only`, `auto_structure_prompt`, `safety_moderation_enabled`, `openrouter_model`, and Hive keys. **If you flip only a toggle** (e.g. "Auto-structure prompts" or "Content moderation"), Save stays disabled and the change can't be persisted. **Fix:** track a dirty flag across all fields and enable Save when anything changed.

**B2 — "Generate from image" reports fake seed/duration.**
`Generate.tsx:295`: on remix success, `gen.setDone(res.image_url, fixedSeed ? seed : 0, 0)`. The inpaint endpoint (`EditResponse`) returns no seed and no duration, so the result card shows **"Seed: 0", "0.0s"**, and the download filename becomes `ideogram-0.png`. **Fix:** have `/api/edit/inpaint` return the resolved seed + duration (it already generates one), or at minimum stop displaying fabricated values.

**B3 — WebSocket close during model-load is swallowed.**
`useGenerate` `ws.onclose` flags an error only when `store.status === "running"`. After a `status` message moves state to `loading-model`, an abnormal close is **not** surfaced — the UI hangs on a spinner. **Fix:** treat any non-1000 close that isn't `done`/`error` as a failure.

### 3.2 Backend bugs / gaps

**B4 — Resolution validation vs. pipeline requirement mismatch.**
`GenerationRequest` enforces multiple-of-16 (`schemas.py:65`), but the pipeline requires multiples of `vae_scale_factor × patch_size` (`pipeline_ideogram4.py:444`). If that product is 32, an accepted 16-aligned size (e.g. 1040²) raises inside the pipeline and surfaces as a generation error. **Fix:** validate against the true alignment (snap to ×32 or read the factor from the loaded pipeline).

**B5 — Disconnected jobs leak as `running` forever.**
On `WebSocketDisconnect` the inference thread keeps running but `complete_job`/`fail_job` are only called in the receive loop, so the DB row stays `running` indefinitely (image still written to `/outputs`, but no `done` row). **Fix:** reap on disconnect (mark failed/cancelled) and/or persist completion independent of the socket.

**B6 — `prompt_text` is effectively always NULL for generated jobs.**
`create_job` is called with only `prompt_json` (`main.py:955`); gallery search does `prompt_json LIKE ? OR prompt_text LIKE ?` — the second clause never matches. Search still works on the JSON, but the column is dead weight. **Fix:** populate `prompt_text` (e.g. the high-level description) so search is more natural, or drop the clause.

**B7 — Inconsistent LoRA guards.** `/api/loras/apply` checks `supports_lora` explicitly, but `/weight` and `/remove` rely on the manager raising. Minor; unify the guard style.

### 3.3 Conflicts

**C1 — Model variant has two sources of truth.** Client `settingsStore.modelVariant` (localStorage, drives the UI) vs server `settings.model_variant` (persisted in `.env`, fetched, ignored). They can silently disagree — server thinks variant X, UI loads variant Y. **Fix:** pick one authority. Recommended: treat the server value as the source of truth on load and hydrate the store from it, or stop returning it.

**C2 — `soft_guidance` semantics differ by path.** Honored in WS generate, dropped in inpaint/extend (B/§2.2-4). Resolving the CFG-control work (P0) should make CFG handling uniform across generate and edit.

### 3.4 Minor / robustness
- `useUpscaleModels` returns `[]` on any non-OK response → the upscale strip silently disappears instead of reporting a backend fault.
- `PromptBar.handleImage` swallows the aspect-match read error with `.catch(() => {})`.
- CORS (`:5173` only) is stricter than the WS origin allow-list (adds `:8000`, any same-host, any no-origin) — intentional for LAN/phone, but worth a comment so it isn't "fixed" by mistake.
- `useInpaint`/`useRemixFromImage` send `sampler_preset` as a plain `string`, bypassing the `SamplerPreset` union (type hole).
- `useSplitLayers` builds its `elements` array from an inline shape, not the shared `types/api.ts` contract (drift risk).

# Part 4 — Recommended implementation roadmap

Ordered to honor "research features first," with bug fixes folded in where they're cheap and on-path.

**Phase 1 — Generation control surface (research P0).** *Biggest payoff.*
1. Add `cfg`, `cfg_override`, `cfg_override_start` to `GenerationRequest` + `GenerationSettings`; build `guidance_schedule` from them per-pipeline direction.
2. New UI: a CFG group (value + override + start %) replacing/extending the `soft_guidance` toggle; presets pre-fill the fields. Default CFG ~3.5 with a late drop.
3. Thread the same CFG settings through inpaint/extend (fixes C2 / §2.2-4).
4. Fold in **B1** (Settings Save dirty-flag) and **B2** (real seed/duration on remix) since they touch the same generate/settings surfaces.

**Phase 2 — Collapse prevention & recovery (research P1).**
5. Short-prompt / empty-canvas guard + "auto-fill background box."
6. Optional collapse detection + auto seed-retry.
7. Fix **B3** (WS close handling) — relevant once retries exist.

**Phase 3 — Power-user knobs & stability (research P2 + backend bugs).**
8. Advanced panel: custom steps + mu/std/shift.
9. Fix **B4** (resolution alignment), **B5** (job reaping), **C1** (model-variant authority).
10. Cleanup: remove `EditRequest`/`rebuild()` dead code, unify LoRA guards, tighten types.

**Phase 4 — Experimental / perf (research P3).**
11. Flash-attention investigation (head-dim-256 speedup).
12. Custom sigma schedule ("ExtendIntermediateSigmas") behind an "experimental" flag — only if Phase 1–2 don't already make collapse a non-issue.
